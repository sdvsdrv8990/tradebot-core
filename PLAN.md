## Принцип: ничего не ломать

Все правки ложатся на существующие швы, конвейер (фильтры → Decision →
exec) не переписывается:

- проверки идентичности — **новые шаги при старте** (fail-fast с
  атрибуцией `TB_G_DEX`), до первого опроса;
- данные (`symbol`, `decimals`, `block`) — **расширение снапшота** и
  геттеров, читатели (морда) только потребляют;
- новые биржи — **только конфиг** (при выполнении В4/В8 ниже):
  `rpc[]` += venue, `pools[]` += пулы; всё остальное подхватывает
  реестр и валидатор.

## Завтра, в порядке выгоды/стоимости

### P0 — мелкие, закрывают показательные дыры (полдня)

- **В1. Свежесть пар на странице** — в `web_build_market` в цикл пар
  добавить тот же `now - ts_ms <= fmax`, что уже считается для таблицы
  пулов. Устаревшая пара исключается (или помечается). ~5 строк.
- **В2. Валидатор конфига при старте** (fail-fast, до сети):
  каждый `pools[].pool` обязан состоять в `rpc[v].pools` ровно одной
  venue; `pools[].dex` обязан совпадать с её именем; дубли адресов —
  ошибка. Отказ с точным сообщением (`config: пул 0x… объявлен
  uniswap-v3, найден в pancake-v3`). Убирает проблему №1 (двойное
  объявление рассинхронизировано быть не может).
- **В3. Честная подпись профита** — колонку «профит/пробу» переименовать
  в «≈ спред-оценка», пока не готов В7.

### P1 — идентичность и достоверность данных (день)

- **В4. Проверка пула на цепи** (закрывает проблему №2): на старте для
  каждого пула `eth_call Factory.getPool(tokenA, tokenB, fee)` → адрес
  из цепи обязан совпасть с конфигом. Фабрика Uniswap V3:
  `0x1F98431c8AD9852364AE8ddf06475563B9961697`; адрес фабрики — новое
  необязательное поле venue (`factory`; нет поля — venue не V3-типа,
  проверка пропускается с предупреждением). Несоответствие → отказ.
  Селектор getPool сверить keccak на месте (как делали для 0xc6a5026a).
- **В5. Символы и decimals токенов с цепи** (убирает C-хардкод):
  на старте `eth_call symbol()` (строка ABI) и `decimals()` для каждого
  токена пулов; кэш в `tb_arb`; неизвестное — короткий адрес, как
  сейчас. Морда получает `symbol` из снапшота — уже готово (поле есть).
- **В6. Привязка к блоку** (проблема №5): в начале батча опроса
  `eth_blockNumber`, все котировки батча — `eth_call` с этим номером
  (второй элемент params), номер блока — в `tb_arb_snap_t`. Пара
  допускается к сравнению только при совпадении блоков двух снапов
  (в движке — фильтр, на странице — исключение/пометка).

### P2 — мульти-DEX по-настоящему (следующие за завтра)

- **В7. Маршрутный профит на странице**: раз в цикл опроса брать
  лучшую пару и прогонять реальную цепочку WETH→TOKEN→WETH через
  `dex_quote_route` (механизм Decision Engine уже существует) —
  в market-снапшот поля `profit_quote` (реальная котировка) рядом с
  `profit_est` (оценка). Одна пара на цикл — без лишнего RPC-шума.
- **В8. Вторая биржа — PancakeSwap V3** (Ethereum): адреса QuoterV2 и
  фабрики взять из официальных доков/деплоев pancakeswap.finance,
  **проверить на цепи** через В4 (не верить докам слепо), добавить
  WETH/USDC пул в конфиг. С этого момента спреды «между биржами»
  становятся настоящими. SushiSwap/Uniswap V2 — отдельный этап:
  нужна механика `getAmountsOut` как ещё один метод котировки за
  `tb_exec_backend_t` (конвейер не меняется).
- **В9. Реестр вместо дубля** (рефакторинг конфига, после В8):
  `pools[]` ссылается на venue по имени, `rpc[].pools` убрать;
  валидатор В2 упрощается. Делать только когда форматы устоятся.

## Источники данных для новых бирж

| Что | Откуда | Проверка |
|---|---|---|
| Адреса Quoter/Factory/пулов | официальные доки биржи (docs.pancakeswap.finance, docs.uniswap.org) | `Factory.getPool` на цепи (В4) + живой smoke `--replay`-подобный прогон котировок |
| Символы токенов, decimals | сама цепь (`symbol()`, `decimals()`) | В5 |
| Цены | только свои котировки QuoterV2 по RPC (PublicNode; при лимитах — свой эндпоинт в конфиге venue) | сверка В7 quote vs est |
| Логотипы | `./logos` (run.sh тянет по slug = имя venue без `-v3`) | буквы-бейджи как фолбэк |

## Явно НЕ делаем завтра

- V2-биржи (Sushi) и мультичейн (Base/Arbitrum) — после В8.
- Переписывание Decision Engine — не требуется.
- Автозагрузку лого из интернета в рантайме — уже локально, хватает.
