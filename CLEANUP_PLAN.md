## Уже закрыто в этом же аудите (коммит b50f42b)

- статистика решающей фазы из воркеров гонялась между перекрывающимися
  батчами → приватные счётчики джобы, перенос на потоке цикла;
- ленивая инициализация ciphersuites mbedTLS без мьютекса → прогрев
  первого `mbedtls_ssl_config_defaults` в `tb_http_net_create`
  (правило: любой новый «первый вызов mbedtls_*» — туда же, до пулов);
- `TB_ARB_MAX_RESULTS` 16 тихо резало мультичейн-батчи → 64.

## Порядок исполнения

1. П1, П4–П6, П11 — один коммит «чистка мусора» (полчаса, риск ноль).
2. П2 — отдельный коммит (лимит + fail-fast).
3. П7, П5 заодно — «дедупликация поиска venue».
4. П8 — «разнос arb.c» самым большим отдельным коммитом: только
   переносами, diff — чистые перемещения функций.
5. П9, П10 — «контракты webui/статистики».
6. П3 — ротация журнала (затрагивает конфиг + ledger.c; тест на
   переименование поколений).
7. П12 — keep-alive транспорта (самостоятельная итерация, TSan
   обязательна; если снята боль — П13/П14 пересмотреть).

После каждого шага: `ctest` + короткий живой прогон; после П8 и П12 —
полные ASan/TSan. Форматы (конфиг, журнал, API морды) не меняются,
кроме добавления опции П3 (обратная совместимость: нет поля — нет
ротации).
